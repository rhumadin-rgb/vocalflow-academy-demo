# 보컬플로우 | 음악학원 운영 데모

보컬 레슨 학원과 연습실 운영 흐름을 체험하는 반응형 웹 예시 프로젝트입니다. 별도 설치나 빌드 없이 `index.html`을 브라우저에서 열어 실행할 수 있습니다.

> **데모 전용:** Supabase 인증 설정을 하지 않으면 로그인 없이 데모로 실행됩니다. Supabase 인증을 설정해도 업무 데이터는 아직 서버 저장이 아니며, 메뉴의 권한 선택은 보안 권한 검사가 아닙니다. 입력한 예시 데이터는 현재 브라우저의 `localStorage`에만 저장됩니다.

## 포함 기능

- 대시보드: 당일 수업, 출결, 수납 및 미납 현황
- 수업·출결: 일정 등록과 출석 기록, 잔여 레슨 및 강사 급여 자동 반영
- 1:1 레슨 피드백: 강사의 수업 코멘트, 집중 영역, 보완점과 다음 연습 과제 기록 및 원생별 확인
- 강사 메뉴의 수업 피드백: 출석 완료된 레슨별 작성 대기/완료 현황과 피드백 수정
- 원생·수납: 원생 등록, 잔여 수강권 확인, 수납 등록과 미납 알림톡 미리보기
- 연습실 예약: 중복 시간 예약 차단, 반별 일일 예약 한도, 노쇼 누적 제한
- 연습실 현황 디스플레이: 별도 창으로 띄우는 전체 공간 현황 화면
- 강사·급여: 출석 수업 기준 급여 계산, 조정 입력, 엑셀 호환 CSV 내보내기
- 수입·지출: 일회성 및 월 반복 내역, 월별 손익 요약
- 설정: 역할별 화면 미리보기, 노쇼 기준, 강사별 회당 급여와 요일별 고정 레슨실 배정
- 역할별 탐색 메뉴: 원장·관리자·강사·원생 보기 권한에 맞춰 왼쪽 메뉴를 표시하고, 권한이 바뀌면 접근할 수 없는 화면에서 대시보드로 이동
- 사용자 관리: 원장·관리자 전용 사용자 추가, 역할별 메뉴 보기 권한 부여 및 계정 활성/중지
- 계정 인증(선택 설정): Supabase 이메일/비밀번호 로그인, 이메일 재설정 링크 및 새 비밀번호 설정
- CSV 데이터 관리: 원생·강사·수업·예약·회계·사용자 목록 가져오기/내보내기, 전체 운영 데이터 백업 및 복원
- 브라우저 `localStorage`를 통한 데모 데이터 저장

## 데모 사용

1. `index.html`을 브라우저에서 열거나 정적 파일 호스팅에서 프로젝트 루트를 게시합니다.
2. 상단의 **보기 권한**을 바꿔 원장·관리자·강사·원생 화면을 확인합니다.
3. 좌측 메뉴를 이용해 수업, 원생, 연습실, 급여, 회계 화면으로 이동합니다.
4. 원장 또는 관리자 권한에서 **사용자 관리** 메뉴를 열어 샘플 사용자를 추가하고 역할별 보기 권한을 지정할 수 있습니다.
5. **설정 → CSV 가져오기 · 백업**에서 목록을 내보내거나 CSV로 가져오고, 전체 백업 파일을 다운로드·복원할 수 있습니다. 목록 CSV는 지정한 종류를 선택하고 ID 기준 병합 또는 전체 교체를 선택합니다.
6. **데모 초기화**를 누르면 현재 브라우저에 저장된 변경 사항을 지우고 샘플 상태로 되돌립니다.

알림톡 발송은 실제 전송이 아니라 대상 선택과 발송 확인을 보여주는 데모입니다. 반복 회계는 매월 첫 실행 때 자동 반영하며, 화면의 **정기 내역 반영** 버튼으로도 처리할 수 있습니다. 급여 내보내기는 엑셀에서 열 수 있는 CSV 파일입니다.

## Supabase 로그인 및 비밀번호 복구 설정

실제 인증을 사용하려면 먼저 Supabase 프로젝트를 준비하세요. `supabase-config.js`의 URL/키가 비어 있으면 로그인 없이 데모 모드로 실행됩니다.

1. `supabase-config.js`에 Supabase 프로젝트 URL과 **publishable/anon 공개 키**를 입력합니다. 이 키는 브라우저에 노출되는 공개 키이므로 데이터 권한은 RLS로 보호해야 합니다. `service_role` 키나 비밀 키는 이 파일에 절대 넣지 마세요. 인증은 `file://` 주소가 아닌 HTTPS 사이트 또는 `http://localhost`에서 테스트합니다.
2. GitHub Pages 등 공개 호스팅에 인증을 적용하려면 설정된 `supabase-config.js`도 함께 배포합니다. URL과 공개 키는 브라우저 공개 값이지만, 변경 시 저장소의 공개 여부와 배포 권한을 확인하세요.
3. Supabase Dashboard의 **Authentication → URL Configuration**에 운영 사이트 URL을 Site URL로 등록하고, `https://<사용자명>.github.io/<저장소명>/login.html`을 Redirect URLs에 추가합니다. 개발 중인 경우 `http://localhost:<포트>/login.html`도 필요한 경우에만 허용 목록에 추가하세요. 로그인 페이지는 `/login.html`이며, 인증된 상태로 앱을 열면 바로 앱으로 이동합니다.
4. **Authentication → Providers → Email**에서 이메일 로그인을 켜고 신규 계정은 Supabase Dashboard에서 초대/생성하세요. 이 데모에는 공개 회원가입 기능이 없습니다. 운영 메일 발송에는 신뢰 가능한 SMTP와 재설정 메일 템플릿을 설정합니다.
5. **Authentication → Settings**에서 비밀번호 최소 길이를 12자로 설정하고, 유출된 비밀번호 차단 기능을 켭니다(프로젝트 플랜/기능 지원 시). 긴 패스프레이즈를 허용하고, 대문자·숫자·특수문자 조합을 억지로 강제하거나 정기 변경을 요구하지 않는 것을 권장합니다. 원장/관리자는 MFA 사용도 권장합니다.
6. 사용자는 별도 로그인 페이지(`/login.html`)의 **비밀번호를 잊으셨나요?**에서 이메일을 입력하고, 메일 링크로 돌아와 새 비밀번호를 설정합니다. 존재 여부를 노출하지 않도록 계정이 없는 경우도 같은 안내를 보여줍니다. 운영 시 메일/로그인 요청 제한, 안전한 계정 복구 절차, 테스트 계정으로 리디렉션과 링크 만료를 확인하세요.

**중요:** Supabase 로그인은 계정 인증만 합니다. 현재의 수업·원생·회계 데이터는 여전히 브라우저 `localStorage`에 있고, 상단의 역할 선택도 누구나 바꿀 수 있는 데모 기능입니다. 따라서 실제 사용자 개인정보를 입력하지 말고 실제 운영 전에 DB/API 연결, RLS 기반 권한 검사와 서버에서의 역할 확인을 별도로 구현해야 합니다.

## 실제 운영 전 필요한 작업

이 MVP는 화면과 브라우저 내 기능 검증용이며 업무 데이터의 서버 저장, 사용자별 계정 데이터 격리, 결제·알림톡·엑셀 `.xlsx` 연동은 포함하지 않습니다. 선택형 Supabase 인증은 이메일 로그인과 비밀번호 재설정만 처리하며, 사용자 관리에서 지정하는 사용자와 역할은 실제 권한이 아닙니다. CSV 가져오기와 백업도 현재 브라우저 데모 데이터만 대상으로 하며 서버 백업이 아닙니다. 현재 데모의 `localStorage` 및 CSV 파일은 암호화되지 않으므로 실제 개인정보를 입력하지 마세요. 실제 운영 배포 전에는 서버 API와 데이터베이스, 인증·인가, 백업, 개인정보 보호, 결제 및 알림톡 사업자 연동을 추가해야 합니다.

정적 예시 페이지를 공개하려면 GitHub 저장소의 **Settings → Pages**에서 배포 대상을 `Deploy from a branch`로 선택한 뒤 `main` 브랜치의 `/(root)` 폴더를 지정하면 됩니다. 공개 URL 설정은 저장소를 공개하지 않고도 가능할 수 있지만, 비공개 저장소의 Pages 제공 여부는 GitHub 요금제에 따라 다를 수 있습니다. 배포 전에는 데모 데이터를 다시 확인하고, 실제 고객 정보나 비밀 키를 추가하지 마세요.

Supabase/PostgreSQL 테이블 구조, 개인정보 필드 암호화 및 적용 순서는 [데이터베이스 가이드](./docs/DATABASE_SCHEMA.md)를 참고하세요. SQL 마이그레이션은 [초기 스키마](./supabase/migrations/202610160001_initial_schema.sql)와 [개인정보 암호화](./supabase/migrations/202610190001_encrypt_personal_data.sql)로 나뉩니다. 현재 데모 앱은 아직 이 데이터베이스를 사용하지 않으므로, DB 암호화는 공개 데모의 브라우저 저장 데이터에 적용되지 않습니다.
